El studio no guarda credenciales: le pide el login al CLI de Claude Code, que es el mismo que usás en la terminal. Iniciar sesión abre el flujo en tu navegador; si el proceso pide un código, pegalo abajo.

Importar LLM

Pegá el link del repositorio. El studio lo clona, busca todo lo que Claude Code cargaría ahí —memoria, skills, comandos, subagentes, hooks, MCP servers, plugins— y redibuja el mapa del ciclo solo con eso: los componentes del plugin salen de la vista. No modifica el repo importado.

Qué es cada cosa

Todos estos nombres son los de Claude Code. Si los aprendés acá, los vas a reconocer en la documentación y en la terminal.

Elegí un componente

Cada chip del ciclo es un archivo real del plugin. Al abrirlo se edita en disco: lo que guardes acá es lo que va a correr.

Clickeá cualquier componente del grafo: si tiene archivo se abre para editar, y si ya corrió se ve lo que dijo el modelo ahí.

Para equipos que no integran con ningún tracker. Lo que escribas acá se guarda como .claude/run/<ID>/story.json, el mismo formato normalizado que produce Jira o ADO — de la fase 1 en adelante el ciclo no distingue de dónde vino.

Es el campo que decide el run: @refinamiento bloquea si faltan o no son verificables. Escribir la historia acá no saltea ese gate.
